# AI mistakes log

Running log, kept by the AI assistant while building. Each entry: what was wrong,
how it was caught, the fix. Raw material for AI_USAGE.md -- the human author
reviews and writes that file.

| # | Phase | What was wrong | How it was caught | Fix |
|---|---|---|---|---|
| 1 | 0 | The no-hardcoding guard's regexes were written through a Python string in a shell heredoc; `\b` became a literal backspace (0x08), so the word-boundary patterns could never match. The two real guard tests **passed** with the broken patterns. | The guard's own self-test (`test_guard_actually_detects_leaks`, which asserts the patterns fire on known leaks) failed. `cat -A` showed `^H` bytes. | Rewrote the block as a raw string, added an assertion that the file contains no 0x08. Lesson: every guard test needs a "does it catch a known-bad input" case. |
| 2 | 1 | First grid post-processing trusted every tracker peak. Beat This! keeps "ticking" 1-3 beats into digital silence at activation ~0.9, so grids started a beat before the music and ran past the end. | Experiment comparing peaks to generated truth: first peak at 0.90 s when the music starts at 1.37 s; RMS at that peak was -240 dB. | Edge trimming by onset support (spectral flux under the beat) in `grid._trim_unsupported_edges`; interior beats are never trimmed. |
| 3 | 1 | Missed/extra-beat repair used a 9-beat running median as its reference period, which *follows* the tracker when it switches metrical level (6/8: dotted quarter <-> eighth), so level switches were preserved instead of repaired. | Synthetic 6/8 @72: four "free" tempo segments at 83-217 BPM in a constant-tempo track. | `_reference_period`: running median, but fall back to the region's dominant period where they disagree by more than a plausible drift. |
